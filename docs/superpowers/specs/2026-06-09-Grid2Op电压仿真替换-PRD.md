## 1. 产品概述与目标

### 1.1 项目背景

当前 MUPC RL 环境（`mupc_env.py`）使用简化 Q-V 耦合三相电压模型（`VoltageSimulator`），该模型以固定灵敏度系数 + 随机噪声模拟电压响应，已不能满足三相电压精度要求。

### 1.2 产品目标

将 `VoltageSimulator` 替换为 Grid2Op + Pandapower 物理仿真引擎，实现：

1. **三相电压精确计算**：基于 Pandapower 潮流计算的真实线路模型，替代现有简化灵敏度系数
2. **RL 训练管线零改动**：保持 `MupcEnv` 的 Gymnasium 接口不变，确保与 `train.py` 完全兼容
3. **奖励函数与动作约束兼容**：现有 5 种场景奖励函数和 5 条动作约束规则（ACT-01~05）无需修改

### 1.3 成功标准

- 替换后 `MupcEnv` 可直接加载现有 checkpoint 并继续训练
- 三相电压计算误差 ≤ 2%（与 Pandapower `runpp` 标准对比）
- 每步仿真耗时 ≤ 50ms（使用 lightsim2grid 加速后端）

## 5. 接口设计约束

### 5.1 硬性约束

以下接口**必须保持不变**：

```python
# MupcEnv Gymnasium 接口（不可修改签名和返回值）
MupcEnv.reset(seed=None, options=None) -> (obs, info)
MupcEnv.step(action: np.ndarray) -> (obs, reward, terminated, truncated, info)

# 观测空间维度（不可修改）
observation_space: Box(58,) 或 Box(59,)  # 单模式/多模式

# 动作空间维度（不可修改）
action_space: Box([−1, 0], [1, 1])  # [p_batt_norm, load_shed_norm]

# 动作约束接口（不可修改）
ActionValidator.validate(action, dispatch_p, q_batt_real) -> (clamped, violated, violations)
```

### 5.2 内部实现灵活性

以下实现可变更，不影响接口兼容性：

- `VoltageSimulator` 类（替换为 Grid2Op Backend）
- `MupcEnv._voltage_sim` 对象（替换为 Grid2Op Env）
- Pandapower 网络拓扑定义
- Grid2Op Chronics 数据注入方式

### 5.3 状态映射要求

| 原内部状态 | Grid2Op 映射 | 验收标准 |
|------------|--------------|----------|
| `_soc` | `storage.soc` | 每步同步 |
| `_va`, `_vb`, `_vc` | `obs.line_status` 或自定义 `BusVoltageObservation` | 三相电压均输出 |
| `_load_rate` | 变压器 `loading` | 偏差 ≤ 0.1% |
| `_grid_power` | `storage.p` + `load.p` + `sgen.p` | 偏差 ≤ 0.1% |

## 6. 风险评估

| 风险编号 | 风险描述 | 影响等级 | 应对策略 |
|----------|----------|----------|----------|
| R-01 | Grid2Op 与 Gymnasium 接口冲突（环境基类不兼容） | 高 | 编写 `Grid2OpGymWrapper` 适配层，仅在 `MupcEnv` 内部使用 |
| R-02 | 潮流计算耗时过高，导致训练速度下降 5~10 倍 | 高 | 优先使用 lightsim2grid C++ 后端；必要时降级为单相潮流 |
| R-03 | 三相潮流收敛失败（孤岛/过载导致潮流不收敛） | 中 | 添加潮流收敛检测，不收敛时回退到上一时刻电压值 |
| R-04 | Grid2Op Chronics 数据格式与现有 `data` dict 不兼容 | 高 | 编写 `DataDictChronics` 自定义类，将 `data` dict 转换为 Grid2Op 时序格式 |
| R-05 | 动作空间映射错误（2维动作未正确映射到 Grid2Op storage） | 高 | 添加单元测试，验证 `action → storage_p` 映射一致性 |
| R-06 | SOC 状态在 Grid2Op 与 MupcEnv 之间不同步 | 高 | 在 `step()` 开始时同步 Grid2Op storage SOC 到 `self._soc`，结束时反向同步 |
| R-07 | 现有奖励函数依赖的观测字段在 Grid2Op 中不可用 | 中 | 审查所有奖励函数使用的观测字段，确保 Grid2Op Observation 类提供等效字段 |
| R-08 | 依赖库版本冲突（pandapower vs grid2op） | 低 | 使用虚拟环境隔离；预先测试版本兼容性矩阵 |

### 6.1 关键风险缓解措施

**R-01 缓解**：采用组合模式，而非继承模式。即 `MupcEnv` 内部持有 `Grid2Op Env` 实例，而非继承 Grid2Op 环境基类。

**R-03 缓解**：每步检查 `env.simulate()` 返回值，若 `has_illegal` 为 True 或电压为 NaN，则保持上一时刻电压不变。

**R-04 缓解**：实现 `DataDictChronics` 类，将现有 `data` dict 的 `load_power`、`pv_power` 等数组按时间步索引转换为 Grid2Op 格式。如果 `DataDictChronics` 因结构性原因无法实现（例如 data dict 缺少 Grid2Op 必需的元数据字段），则本次替换需重新评估可行性，或降级为混合方案（保留原 data dict 直接注入路径，不经过 Grid2Op Chronics）。
