## 变更 1：归一化范围修正（4 字段）

### 背景

下游 PRD §v3.1 注释中的"部署归一化范围"表格标称来自 MUPC-AI2 `constants.py`，
但实际值与训练管线不一致。训练管线的归一化范围是权威来源（RL 模型在此空间训练）。

### 修正内容

`normalize_observation()` 中以下 4 个字段的 MinMax 归一化范围需要更新：

| 字段 | 观测索引 | 旧范围（当前 Rust 代码） | 新范围（对齐训练） | 训练依据 |
|------|---------|------------------------|-------------------|---------|
| `battery_soc` | [0] | `[0.1, 0.9]` | `[0.0, 1.0]` | `mupc_env/constants.py:73 NORM_SOC` |
| `transformer_load` | [4] | `[0.0, 1.5]` | **不作归一化 (identity)** | `mupc_env/observation.py:292` 直接透传 |
| `solar_irradiance` | [45] | `[0.0, 1000.0]` | `[0.0, 1500.0]` | `mupc_env/constants.py:82 NORM_IRRADIANCE` |
| `temperature` | [46] | `[-10.0, 45.0]` | `[-20.0, 60.0]` | `mupc_env/constants.py:83 NORM_TEMPERATURE` |

### Rust 修改位置

- **文件**: `mupc/crates/ai-engine/src/data_fusion.rs`
- **函数**: `normalize_observation()`
- **操作**: 修改上述 4 字段的 `min`/`max` 参数；`transformer_load` 改为 identity 透传

### PRD 已同步

`docs/MUPC/05-MUPC-AI引擎-PRD.md` 中的归一化范围表格已同步更新为上述新值。

## 变更 2：k_droop 动作空间范围修正

### 背景

下游 `parse_action_output()` 对 k_droop 硬编码 `clamp(0.0, 30.0)`，但训练管线此前使用
`[-100, 100] kW/V` 范围训练 RL 模型，导致训练与部署的动作空间不一致。

### 已修正（训练侧）

训练管线已对齐下游，将 k_droop 范围从 `[-100, 100]` 改为 `[0, 30]`：

| 文件 | 修改 |
|------|------|
| `mupc_env/constants.py` | `K_DROOP_MIN = 0.0`, `K_DROOP_MAX = 30.0` |
| `mupc_env/action_validator.py` | 类默认值 + 去归一化映射 |
| `config/mupc_env_config.yaml` | `k_droop_min: 0.0`, `k_droop_max: 30.0` |
| `config/config_manager.py` | dataclass 默认值 |

去归一化公式：`k_droop = tanh_output * 15.0 + 15.0` → `[0, 30] kW/V`

### 下游侧：无需修改

下游 `parse_action_output()` 原本就是 `(raw[1] as f64).clamp(0.0, 30.0)`，与训练新范围一致。
**注意**：如果下游 Rust 代码中还有其他位置引用了旧的 k_droop 范围 `[-100, 100]`，需要清理。

## 变更 3：ONNX 策略模型归一化

### 背景

训练管线的 ONNX 导出 (`export_onnx.py`) 以前内置了一个不完整的归一化层
（仅对 D1 前 8 维做简单线性缩放，不处理偏移）。此层已被移除。

### 修正后

ONNX 策略模型现在是**纯策略网络**，期望输入**已归一化的 78 维观测向量**。
归一化完全由下游 `normalize_observation()` 负责（完全镜像训练环境 `observation.py:normalize_obs()`）。

### 下游侧：确认事项

1. `normalize_observation()` 是否对全部 78 维做 MinMax 归一化？
2. 归一化值的索引位置是否与训练 `observation.py:normalize_obs()` 一致？
3. ONNX 推理输入是否经过 `normalize_observation()` 后再送入 RKNN Runtime？
