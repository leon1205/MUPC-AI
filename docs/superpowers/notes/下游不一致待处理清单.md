## 已处理的下游不一致（历史）

### ✅ #1 SafetyOverride reason_code 字段不一致 (2026-06-17 下游 v2.15 修复)

**原始问题**：下游 v2.14 已删除 `safety_override_reason_code` 字段（D9 4 字段：active/p_ref/consecutive/ratio），但 v2.15 PRD 7.2 仍按 4 个原因差异化。

**下游 v2.15 处理**：
- 删除 `match reason { voltage_violation/q_exhausted/emergency/... }` 分支
- 样本不足时统一使用固定惩罚 -3.33（≈ 原 voltage_violation -50/15 档位）
- 样本充足时维持 `(-5·ratio - 10·(consecutive/10).clamp(0,1))/15`
- 设计文档新增 `cold_start_penalty = 3.33` 配置项

**本地训练管线验证**：
- `_compute_safety_override()` 实现：`consecutive<10 → -50/15 ≈ -3.333`, `consecutive≥10 → (-5·ratio - 10·(consecutive/10).clamp(0,1))/15`
- 与下游公式完全一致（-3.33 与 -50/15 ≈ -3.333 数值差异 ~0.1%，可接受）

### ✅ #2 SCENE-B1 P_battery_degradation 公式形式差异 (2026-06-17 下游 v2.15 修复)

**原始问题**：下游 v2.15 Section 7.3 公式：`β·Σ(|P_batt_set|·Δt)/E_battery_total·100`（累积能量），与本地训练管线 C-rate² 不等价。

**下游 v2.15 处理**：
- 公式改为 `β · (|p_ref| / E_battery_total)²`（C-rate² 应力模型）
- 下游 PRD 7.3 加 v2.15 修正说明：与上游训练管线、`reward_calculator.rs` 实现、§5.3 SCENE-01 子项定义三处保持一致
- SCENE-01 引入 α(s) 自适应系数（极低 SOC=3.0，电压支撑=0.2），SCENE-B1 可选启用（β 即此处 α）

**本地训练管线验证**：
- `_reward_arbitrage()` 实现 `c_rate = abs(r["p_batt"]) / BATTERY_CAPACITY_KWH; p_batt_deg = c_rate ** 2`
- 与下游 C-rate² 公式完全一致 ✅
