## 待下游澄清项

### 1. SafetyOverride reason_code 字段不一致

**问题描述**：
- 下游 PRD v2.14 (`docs/MUPC/05-MUPC-AI引擎-PRD.md` 历史变更说明) 已**移除** `safety_override_reason_code` 字段（D9 4 字段：active/p_ref/consecutive/ratio）
- 下游 PRD v2.15 Section 7.2 (SCENE-01 SafetyOverride 惩罚公式) **仍按 4 个原因差异化**：

```rust
if consecutive < 10 {
    // 样本不足：原因固定惩罚 / 15
    match reason {
        "voltage_violation" => -50.0 / 15,
        "q_exhausted" => -30.0 / 15,
        "emergency" => -100.0 / 15,
        _ => -20.0 / 15,
    }
}
```

**冲突点**：FusedSystemState v2.14 已无 `safety_override_reason`，但奖励函数 v2.15 仍按 reason 匹配。

**本地处理策略**：训练管线按 v2.14 D9 字段实际传递的 4 字段处理（不依赖 reason_code），SafetyOverride 公式采用统一惩罚，不再按原因差异化。

**建议下游处理**：
- 选项 A：保留 reason_code 字段（v2.14 删除决策回滚），奖励函数 v2.15 公式维持
- 选项 B：维持 v2.14 删除决策，奖励函数 v2.15 改为不依赖 reason 的统一公式（如统一 -50/15）
- 选项 C：奖励函数 v2.15 简化为 `if consecutive<10: -X (常数), else: -5·ratio - 10·(consecutive/10).clamp(0,1)`

### 2. SCENE-B3 容量/里程价格配置项缺失

**问题描述**：
- 下游 PRD v2.15 Section 7.5 写 `R_ancillary_service = P_regulation_capacity·capacity_price + P_regulation_mileage·mileage_price`
- 下游 PRD 缺少 `capacity_price` / `mileage_price` 在 FusedSystemState 或配置中的字段定义
- 本地训练管线目前使用硬编码占位值（capacity=0.1 元/kW, mileage=0.05 元/kW）

**建议下游处理**：
- 在 FusedSystemState 或 `dispatch_p_set` 关联字段中提供 capacity_price / mileage_price
- 或在配置文档中明确定义默认值，供训练管线使用

### 3. SCENE-B1 P_battery_degradation 公式形式差异

**问题描述**：
- 下游 PRD v2.15 Section 7.3 公式：`P_battery_degradation = β·Σ(|P_batt_set|·Δt)/E_battery_total·100`
- 本地训练管线实现：C-rate² = (|p_batt|/BATTERY_CAPACITY)²
- 数值上**不等价**：下游是累积绝对能量（健康度损失），本地是 C-rate²（瞬时应力）

**本地处理策略**：训练实现采用 C-rate² 简化形式（瞬时应力，与训练 RL 优化的常见做法一致），部署侧 Rust 实现按下游 PRD 公式（累积能量）。

**建议下游处理**：
- 在下游 PRD 中明确"训练/部署实现可采用简化近似，但物理量纲需对齐"
- 或在 Section 7.3 提供 C-rate² 简化形式作为训练侧等价公式
