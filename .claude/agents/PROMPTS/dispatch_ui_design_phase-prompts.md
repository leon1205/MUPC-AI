## 执行步骤

### 第一步：调度UI/UX设计师

请你立即调度**UI/UX设计师**开始工作。核心任务是：

1. **需求理解**：深入理解PRD中的用户角色、使用场景和功能流程
2. **风格定义**：确定与产品定位相符的视觉风格，建立设计系统基础
3. **原型设计**：绘制关键页面的线框图或高保真原型，并详细描述交互逻辑
4. **文档产出**：将完整的设计规范整理成文档，内容应包含：
   - 设计风格定义（配色方案、字体、间距规范）
   - 核心组件的设计规范
   - 关键页面的布局与交互说明（可配图文或原型图）
   - 响应式设计说明
   - 文档保存于 `docs/UI_UX_DESIGN.md`

### 第二步：调度UI评审员

UI设计文档完成后，请你立即调度**UI评审员**开始工作。核心任务是：

1. **视觉比对**：将实现页面与设计稿进行逐像素比对
2. **体验走查**：实际操作页面，检查交互流程是否流畅
3. **清单审查**：
   - **还原度**：间距、字体大小、颜色、圆角、阴影等样式属性是否一致？
   - **响应式**：在不同屏幕宽度下，布局是否正常？
   - **交互与状态**：所有按钮、链接的悬停、点击、禁用状态是否实现？
   - **细节**：图片是否有alt文本？加载中、空数据等状态是否有友好提示？
4. **做出裁决**：
   - 如果实现与设计稿一致且体验良好，可标记为 `[DESIGN_APPROVED]`
   - 否则，列出所有差异点，打回修改

### 第三步：门禁检查

作为项目经理，你必须检查：

- UI设计相关产出是否获得了 `[DESIGN_APPROVED]` 标记
- **只有看到此标记**，UI设计合同才算完成，前端开发工作方可依据此设计展开

## 约束与红线

1. **拒绝过度设计**：避免使用影响性能或分散用户注意力的复杂动画
2. **可访问性**：确保颜色对比度达标，信息不止依靠颜色传递
3. **用户体验至上**：如实现符合设计稿但实际体验差，有权提出优化建议
